# PILGRIM — роадмап MVP (демо)

**Цель:** кликабельное демо MVP сайта-сообщества на GitHub Pages, чтобы заказчик его посмотрел.

**Рамки:** делаем только фронт. Данные берутся из типизированных моков в форме будущего DRF API, поэтому бэкенд потом подключается без переделки UI. Бэкенд и инфраструктура из ТЗ вынесены в отложенный **Этап B**.

## Зафиксированные решения

- Next.js (актуальный stable) + TypeScript, App Router, статический экспорт `output: 'export'`.
- Стили только свои: CSS Modules + CSS-переменные. **Tailwind и UI-библиотеки не используем.**
- Монорепо: `pilgrim_front/` — фронт, `pilgrim_back/` — бэкенд (Этап B).
- Репозиторий публичный, деплой через GitHub Actions → GitHub Pages.
- Язык интерфейса — только русский.

## Правила работы

- Один этап = одна сессия. В конце этапа отмечаем чекбоксы и пишем строку в «Журнал».
- Этап сдаётся, когда зелёные `lint`, `type-check` и `build`. Визуальные правки проверяем в Playwright на 360 / 768 / 1280px: без горизонтального скролла.
- Коммит и пуш — только по команде. Каждую новую зависимость согласуем.
- Комментарии в коде по минимуму, код самодокументируется именами и структурой.

| Домен `.ru` | у любого регистратора | ≈ 20–25 ₽/мес в пересчёте с годовой оплаты — оценка, сверить у регистратора |
| SSL | Let's Encrypt через Caddy, автопродление | 0 ₽ |
| Бэкапы вне сервера | rclone в бесплатное облако (Яндекс Диск / Облако Mail.ru) | 0 ₽ |
| Донаты | платёжный сервис | только комиссия с платежей |
| **Итого** | | **≈ 445–475 ₽/мес** — в 450 ₽ укладывается только при оплате на год и скидке 15%; при −10% выходит ≈ 470 ₽ |

Запасной вариант — AdminVPS **Lite**: 1 ГБ RAM, 15 ГБ NVMe, 349 ₽/мес помесячно. Сервер Next.js туда не помещается, поэтому работаем в экономном режиме:
- фронт — статика, данные браузер запрашивает у API при открытии страницы;
- минус режима: поисковики видят контент хуже;
- swap 2 ГБ, урезанный PostgreSQL или SQLite (по согласованию с заказчиком), сборка только в CI.

Перед оплатой проверить в конфигураторе и поддержке:
- [ ] публичный IPv4 входит в цену (на странице не указано);
- [ ] процессор гарантированный или общий;
- [ ] итоговую скидку за 12 мес. (на странице расхождение: 15% или 10%);
- [ ] локация — Россия, образ Ubuntu LTS;
- [ ] **первый месяц оплатить помесячно**, проверить скорость и стабильность, затем перейти на годовую оплату.

Бюджет памяти на Promo (2 ГБ): ОС и Docker ~300 МБ, PostgreSQL ~150 МБ, Django ~200 МБ, сервер Next.js ~150–250 МБ, Caddy ~30 МБ — **≈ 0,9 ГБ**, остальное — запас и кэш, плюс swap 2 ГБ.
Бюджет диска (30 ГБ): ОС ~3 ГБ, образы ~1,5 ГБ, база < 1 ГБ — **≈ 20 ГБ под фото**. При WebP-нарезке это десятки тысяч снимков.

  - [ ] платёжный сервис — позже, кандидат VK Донат (см. B5).
- [ ] **B1.** Django + DRF в `pilgrim_back`, PostgreSQL:
  - модели Category, Event, Post, PostImage, Album, Photo;
  - сериализаторы по `docs/api-contract.md`;
  - django-filter, пагинация;
  - PostgreSQL с урезанной памятью: `shared_buffers` 128 МБ, `max_connections` 20.
- [ ] **B2.** Django-админка — служебная, для организатора: категории, пользователи и роли, массовые операции, аварийный доступ. Тема **django-unfold**, чтобы выглядела современно. Повседневное редактирование — на сайте (B12):
  - CRUD мероприятий;
  - перенос мероприятия в архив (action);
  - категории;
  - посты микроблога с фото inline;
  - альбомы и фото;
  - при сохранении Django сообщает фронту, что данные изменились (см. B4), — новое видно при следующем открытии страницы, без пересборки.
- [ ] **B3.** Медиа:
  - при загрузке Pillow нарезает WebP 1600 и 760 px, оригинал не хранится;
  - файлы лежат в volume на диске сервера, отдаёт их Caddy;
  - S3 подключаем только при нехватке диска.
- [ ] **B4.** Фронт — **сервер Next.js** (`output: 'standalone'`) в Docker:
  - страницы рендерятся на сервере с данными из API Django (`fetch` вместо моков, сигнатуры функций api-слоя не меняются) — новые мероприятия, посты и фото видны при следующем открытии страницы;
  - кэш ответов API: `revalidate` ~60 с плюс сброс по тегу — Django при сохранении вызывает `POST /api/revalidate` фронта с секретом, обновление сразу;
  - новые адреса (`/events/<slug>`, `/blog/<slug>`, `/gallery/<slug>`) открываются без пересборки;
  - фильтры, календарь и «сегодня» по-прежнему считаются на клиенте;
  - демо на GitHub Pages остаётся статическим экспортом на моках: `output: 'export'` включается переменной окружения только для сборки демо.
- [ ] **B5.** Донаты — предпочтительно **VK Донат**:
  - принять платёж прямо на сайте через VK Донат нельзя, платёжного API у него нет (методы `donut.*` только проверяют подписку);
  - интеграция — переход по ссылке: на `/donate` и в CTA «Поддержать» кнопка «Поддержать через VK Донат» ведёт на страницу доната сообщества. Форму с суммами заменяем описанием уровней. Бэкенд, договор и вебхуки не нужны;
  - владельцу сообщества проверить: подключается ли «Монетизация → VK Донат» (в одном источнике указан порог больше 5000 подписчиков), комиссию (по источникам 5–10%) и адрес страницы доната;
  - запасной вариант, если VK Донат недоступен: ЮKassa / CloudPayments / Т-Касса, эндпойнт `POST /donations/` и вебхук на Django.
- [ ] **B6.** VK: виджет сообщества или посты через VK API.
- [ ] **B7.** Сервер AdminVPS Promo:
  - Ubuntu LTS **без ispmanager** (панель лишняя и ест память);
  - вход по SSH-ключам, ufw (22/80/443), fail2ban, unattended-upgrades, swap 2 ГБ;
  - Docker Compose: `caddy` (reverse proxy, раздача медиа, автоматический HTTPS), `next` (сервер фронта), `django` (gunicorn, 2 воркера), `postgres`;
  - маршруты Caddy: `/api/*` и `/admin/*` → Django, `/media/*` → файлы с диска, всё остальное → Next;
  - ротация логов Docker (`max-size`);
  - домен: A-записи на IP сервера для домена и `www`;
  - секреты в `.env` на сервере и в GitHub Secrets, в git не попадают;
  - почтовые порты могут быть закрыты — письма отправлять через внешний сервис по API.
- [ ] **B8.** CI/CD в GitHub Actions — **на сервере ничего не собираем**:
  - бэк: тесты, образ в GHCR;
  - фронт: lint, type-check, build, образ в GHCR;
  - на сервере `docker compose pull && up -d` по SSH;
  - контент из админки в CI не участвует, он сразу пишется в базу.
- [ ] **B9.** Бэкапы:
  - еженедельный бэкап сервера AdminVPS (бесплатно);
  - ночной `pg_dump` и медиа через rclone вне сервера;
  - ежемесячная проверка восстановления.
- [ ] **B11.** Вход и роли:
  - логин и пароль, без публичной регистрации — аккаунты заводит организатор;
  - сессии Django и CSRF (фронт и API на одном домене за Caddy);
  - роли через группы Django и права DRF: «Организатор» — всё, «Активист» — только своё;
  - защита от перебора паролей (django-axes);
  - сброс пароля делает организатор; письмами — только через внешний почтовый сервис, порты почты на VPS могут быть закрыты.
- [ ] **B12.** Редактор на сайте поверх API — формы этапа 11 переходят с IndexedDB на DRF:
  - фото загружаются multipart, нарезка WebP на сервере, лимит размера файла;
  - черновики;
  - текст очищается на сервере (nh3);
  - после сохранения сбрасывается кэш фронта (B4);
  - права проверяются на сервере, а не только в интерфейсе.
- [ ] **B10.** Мониторинг:
  - эндпойнт `/health`;
  - бесплатный внешний uptime-монитор;
