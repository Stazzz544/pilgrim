# PILGRIM — правила проекта

- **Общение — только на русском.**
- Работаем по `ROADMAP.md`: один этап за сессию. В конце этапа отмечаем чекбоксы и пишем строку в «Журнал».
- **Коммит и пуш — только по явной просьбе.** Новые зависимости — только по согласованию.
- Демо публикуется на GitHub Pages: фронт — статический экспорт, данные — моки. Бэкенд (`pilgrim_back`) — отложенный Этап B.

## Next.js 16.4

- Перед кодом сверяйся с документацией своей версии в `pilgrim_front/node_modules/next/dist/docs/` — API отличаются от старых версий.
- `output: 'export'`: нет серверных функций, Server Actions, rewrites/redirects, cookies. У динамических роутов обязателен `generateStaticParams`.
- `basePath` задаётся из `NEXT_PUBLIC_BASE_PATH`. `next/link` префиксует его сам, а пути к файлам из `public/` и `src` у картинок — только через `asset()` из `@/shared/lib/asset`.
- В Git Bash сборка с basePath запускается с `MSYS_NO_PATHCONV=1`, иначе `/pilgrim` превращается в `C:/Program Files/Git/pilgrim`.
- На Windows `next build` кладёт файлы префетча сегментов в папки вместо `__next.a.b.txt` (баг экспорта 16.4), поэтому локально префетч отдаёт 404. На Linux в CI это не воспроизводится, навигация при этом работает.
- Деплой: `.github/workflows/deploy.yml` на push в `main`. basePath и URL сайта берутся из `actions/configure-pages`.
- Всё, что зависит от текущей даты (предстоящие или архив, «сегодня» в календаре), считается на клиенте, а не при сборке.

## Код

- **Tailwind, CSS-in-JS и UI-библиотеки запрещены.** Стили — CSS Modules (`*.module.css`) и глобальные токены `var(--*)`.
- Цвета только через токены, хардкод hex в модулях запрещён.
- Адаптив обязателен на 360 / 768 / 1280px. Сначала fluid-раскладка (`auto-fit/minmax`, `min-width: 0`, `flex-wrap`), `@media` — в последнюю очередь.
- Структура `src/` (FSD-lite), нижние слои не импортируют верхние:
  - `app` — роуты;
  - `widgets` — блоки страниц;
  - `entities/{event,post,album}` — карточки и модели сущностей;
  - `shared/{ui,lib,api,config,styles}` — общий код;
  - `mocks` — демо-данные.
- Импорты через алиас `@/*`. Компоненты экспортируются по имени, кроме файлов-конвенций Next (`page`, `layout` и т. п.). Типы пишутся через `type`, `any` запрещён.
- Комментарии по минимуму: только неочевидное «почему», одной строкой.
- Тексты интерфейса на русском, хардкодом.
